# Kemtiz Messenger 3.0.0 — сервер на Windows

Этот комплект исправляет WebSocket для сообщений в реальном времени и сигнализации видеозвонков, запускает API на компьютере и включает публикацию HTTPS из интернета через Tailscale Funnel. Старый Cloudflare Quick Tunnel для этого комплекта не нужен.

## 1. Установка и запуск сервера

1. Установи Python 3.12+ с https://www.python.org/downloads/windows/ и включи Add Python to PATH.
2. Распакуй весь ZIP в папку, например C:\\Kemtiz.
3. Запусти start_kemtiz_server.bat.
4. Скрипт обновит зависимости, включая WebSocket support. При первом запуске нужен интернет.
5. На ПК проверь http://127.0.0.1:8000/health — ожидается password_auth: true и версия API 0.4.0.
6. Оставь чёрное окно сервера открытым. База и ключ хранятся в kemtiz-data; не удаляй эту папку.

Если сервер уже работал со старой версией, останови старое окно Ctrl+C и запусти новый start_kemtiz_server.bat из распакованного пакета 2.9.0. Не запускай старый пакет 2.6.0.

## 2. Быстрый тест в одной Wi-Fi-сети

1. Подключи телефон и ПК к одному Wi-Fi.
2. В командной строке Windows выполни ipconfig и найди IPv4 адаптера Wi-Fi, например 192.168.0.40.
3. В Kemtiz → СВОЙ СЕРВЕР введи http://192.168.0.40:8000, подставив свой адрес. Нажми «Сохранить и проверить сервер».
4. Проверь регистрацию, заявки в друзья и сообщения.

Если Windows спросит, разреши Python работать в частной сети.

## 3. Доступ из любой сети (публичный HTTPS)

Для друзей вне твоего Wi-Fi используй Tailscale Funnel — он публикует сервер ПК по HTTPS. Установи Tailscale для Windows: https://tailscale.com/download/windows, открой приложение и войди в аккаунт. Затем:

1. Запусти start_kemtiz_public.bat.
2. Если Tailscale попросит подтвердить Funnel/HTTPS в браузере, подтверди.
3. Скопируй URL вида https://имя-устройства.имя-сети.ts.net из окна.
4. Вставь URL в Kemtiz → СВОЙ СЕРВЕР и проверь сервер. Друзьям достаточно установить APK и ввести этот URL — им не нужно быть в твоём Wi-Fi или устанавливать Tailscale.

Держи включёнными ПК, серверный BAT и Tailscale. Публичный адрес доступен только пока компьютер, сервер и Funnel работают. Не публикуй URL открыто: любой, у кого есть ссылка, сможет обращаться к API.

## 4. Звонки и уведомления

Звонок можно проверить между двумя аккаунтами в личном чате. На обеих сторонах должен работать новый сервер с WebSocket support, и приложение должно иметь разрешения на камеру, микрофон и уведомления. Видео передаётся напрямую через WebRTC/STUN, но некоторые мобильные сети требуют TURN-релея.

Версия 3.0.0 показывает Android-уведомления о входящих сообщениях и звонках, пока Kemtiz подключён к серверу и процесс приложения не остановлен системой. На Android 13+ разреши уведомления после появления запроса.

Это пока не полноценные push-уведомления при принудительно закрытом приложении. Для гарантированной доставки в фоне нужна Firebase Cloud Messaging конфигурация — отдельный Firebase-проект и серверные credentials, которые должен создать владелец проекта.

## 5. Push-уведомления

Push после закрытия приложения работают через Firebase Cloud Messaging. Для настройки один раз создай Firebase-проект и добавь Android-приложение с package name `com.kemtiz.app`.

1. Скачай из Firebase Console `google-services.json` и положи его в папку `kemtiz-data` рядом с базой сервера.
2. В Firebase Console → Project settings → Service accounts создай JSON-ключ сервисного аккаунта. Положи его туда же с именем `firebase-service-account.json`.
3. Перезапусти `start_kemtiz_server.bat`. Проверь `/health`: поле `push_notifications` должно стать `true`.
4. На каждом телефоне открой Kemtiz с интернетом, войди в аккаунт и разреши уведомления. Клиент получит публичные параметры Firebase с сервера и зарегистрирует устройство автоматически.

**Не загружай `firebase-service-account.json` в GitHub и никому не отправляй:** в нём закрытый ключ. Не включай его в архив для друзей.

Android/лаунчер управляет внешним видом значка: Kemtiz включает badge и номер, но красный цвет точки поддерживают не все оболочки. После принудительной остановки Android может приостановить push до следующего открытия.

## Безопасность

HTTP-адрес вида http://192.168...:8000 используй только в доверенной домашней сети для теста. Для интернета используй только HTTPS-адрес ts.net. Kemtiz всё ещё альфа-версия: сквозное шифрование, отправка файлов, голосовые сообщения и постоянный TURN-релей ещё не реализованы.
