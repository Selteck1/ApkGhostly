# Kemtiz

Kemtiz — тестовый мессенджер для Android и Windows. В Android используется Google Sign-In, а на Windows вход выполняется через QR-код с подтверждением в уже авторизованном приложении на телефоне.

## Сборки

После успешного GitHub Actions workflow **Build Kemtiz Desktop and Android** в разделе Releases доступны:

- `Kemtiz-Setup.exe` — установщик Windows с ярлыком на рабочем столе.
- `Kemtiz.exe` — портативная версия Windows.
- `Kemtiz-Android-LAN.apk` — Android APK со встроенным сканированием QR-кода.
- `Android-OAuth-SHA1.txt` — SHA-1 именно того APK, который находится в этом релизе.

## QR-вход на ПК

ПК создаёт одноразовый QR-сеанс сроком на 3 минуты. Отдельный секрет опроса сохраняется только в настольном приложении; сканирование само по себе не выдаёт доступ. Android-клиент запрашивает сведения о сеансе, показывает пользователю диалог «Разрешить вход», а сервер передаёт аккаунт ПК только после подтверждения авторизованным пользователем. Повторное использование QR-сеанса отклоняется.

## Локальный режим разработки

Для разработки backend можно запустить локально из исходников в Termux или на компьютере:

```sh
python -m pip install -r kemtiz/requirements.txt
cd kemtiz
uvicorn server:app --host 127.0.0.1 --port 8000
```

Windows EXE теперь является **клиентом общего сервера** и не содержит backend или файл базы данных. При первом запуске он попросит HTTPS-адрес сервера; тот же адрес надо указать в Android-приложении. `http://localhost:8000` допустим только для локальной разработки.

Данные старого сервера Termux сами по себе не переносятся в облачную базу. В этой ранней версии перенос аккаунтов/сообщений нужно планировать отдельно.

## Общий сервер для интернета

Для QR-входа из разных сетей телефон и ПК должны использовать **один API и одну общую базу PostgreSQL по HTTPS**. Для этого репозиторий теперь содержит конфигурацию Render (файл `render.yaml`) и инструкцию развёртывания: [kemtiz/DEPLOY.md](kemtiz/DEPLOY.md).

Важно: публичный сервер ещё нужно создать в аккаунтах хостинга. Пока Render и Neon не настроены, приложение не имеет готового постоянного облачного URL. Не публикуй строку подключения базы данных, секрет подписи сессий или другие секреты и не добавляй их в EXE/APK.

Бесплатный веб-сервис Render может засыпать после периода бездействия, поэтому первое подключение иногда медленное. Для тестового запуска это нормально; для всегда доступного мессенджера понадобится постоянно работающий сервер.

## Backend и проверки

- FastAPI с SQLite для локального режима разработки и PostgreSQL для общего размещённого сервера.
- OAuth ID-токены Google проверяются сервером через HTTPS.
- Поддерживаются друзья, запросы, личные и групповые чаты, группы и WebSocket.
- Вход на ПК использует одноразовый QR-сеанс с отдельным секретом опроса; доступ выдаётся только после подтверждения на уже авторизованном телефоне.
- Workflow проверяет синтаксис backend и frontend, запускает тесты API и собирает APK, EXE и установщик.

Подробная инструкция Windows: [kemtiz/desktop/README.md](kemtiz/desktop/README.md).
