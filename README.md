# Kemtiz

Kemtiz — тестовый мессенджер для Android и Windows. В Android используется Google Sign-In, а на Windows вход выполняется через QR-код с подтверждением в уже авторизованном приложении на телефоне.

## Сборки

После успешного GitHub Actions workflow **Build Kemtiz Desktop and Android** в разделе Releases доступны:

- `Kemtiz-Setup.exe` — установщик Windows с ярлыком на рабочем столе.
- `Kemtiz.exe` — портативная версия Windows.
- `Kemtiz-Android-LAN.apk` — Android APK со встроенным сканированием QR-кода.
- `Android-OAuth-SHA1.txt` — SHA-1 именно того APK, который находится в этом релизе.

## QR-вход на ПК

ПК создаёт одноразовый QR-сеанс сроком на 3 минуты. Отдельный секрет опроса сохраняется только в настольном приложении; сканирование само по себе не выдаёт доступ. Android-клиент запрашивает сведения о сеансе, показывает пользователю диалог «Разрешить вход», а сервер передаёт аккаунт ПК только после подтверждения авторизованным пользователем. Повторное использование QR-сеанса отклоняется.

## Проверка в локальной сети

По умолчанию Windows-приложение запускает API и SQLite-базу на самом ПК, на порту 8000. Адрес ПК показывается в окне QR-входа. Чтобы проверить QR-вход:

1. Запусти Kemtiz на ПК и подключи ПК и телефон к одной доверенной Wi-Fi сети.
2. Настрой Android-приложение на адрес сервера, показанный в Windows-приложении (например, `http://192.168.1.20:8000`).
3. Войди через Google на телефоне, нажми **«Подключить компьютер»**, отсканируй QR-код и подтверди запрос.
4. При проблемах проверь брандмауэр Windows. Не публикуй порт 8000 в интернете: LAN HTTP не шифруется.

Данные локального сервера Windows хранятся в `%APPDATA%\Kemtiz\data`. Перенос существующей базы Termux не выполняется автоматически.

## Общий сервер для интернета

В приложениях предусмотрена настройка одного и того же серверного адреса. Для работы через разные сети нужен отдельно развернутый сервер с HTTPS и постоянным хранилищем. Публичный сервер, домен и облачная база данных этим репозиторием не создаются автоматически, поэтому локальный preview не следует считать полноценным облачным запуском. Никогда не коммить приватные ключи или файл базы данных в репозиторий.

## Backend и проверки

- FastAPI + SQLite.
- OAuth ID-токены Google проверяются сервером через HTTPS.
- Поддерживаются друзья, запросы, личные и групповые чаты, группы и WebSocket.
- Вход на ПК использует одноразовый QR-сеанс с отдельным секретом опроса.
- Workflow проверяет синтаксис backend и frontend, запускает тесты API и собирает APK, EXE и установщик.

Подробная инструкция Windows: [kemtiz/desktop/README.md](kemtiz/desktop/README.md).
